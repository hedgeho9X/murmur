# 实时转写选型与显示规则

## 当前候选与已有验证

调研任务“调研近期 ASR 模型与中文实时转写选型”选定 `qwen-audio-3.0-asr-flash-streaming`，使用北京地域完成了单次流式接口验证。

测试输入为 8.84 秒中文合成音频，以每 100ms 一包、接近真实录音的速度发送：

| 项目 | 结果 |
| --- | --- |
| 发送音频到首次非空文字 | 355ms |
| 结束发送到最终文本 | 342ms |
| 结束发送到任务完成 | 343ms |
| 完成事件 | task-finished |
| 最后一句 | 完整保留 |

这是接口与收尾流程验证，不是模型横向评测或线上延迟承诺。尚未验证 Android 真机、真人口音、噪声、中英混说、并发和长录音。

中间结果存在后续修正，partial 必须按当前片段替换，不能把每次返回全文重复追加。最终片段再合并到完整草稿。

## 客户端呈现

- 录音时照片淡出，去掉取景框背景，波形位于记录区域中央。
- 识别文字位于波形下方，仅一行，按可用宽度保留能容纳的尾部字符。
- 静音时文字与波形留白，完整转写继续保存在草稿。
- 真实实现应区分音频静音与识别服务延迟，不能仅凭暂时没有 partial 就判断用户没说话。
- 点击停止后收齐结束事件和最终文本，再交给统一编辑器。
- HTML 原型使用固定文本模拟以上交互，未接入真实识别；不在前端保存供应商密钥。

测试结论来源为同日独立任务的 asr-streaming-probe.json；本文件只收录非敏感结论，不包含业务空间地址或凭据。

## 原生实现

`SpeechRecorder.kt` 通过 AudioRecord 采集 16 kHz PCM16，使用生成的 AsrStart/AsrFinish/AsrServerEvent 及 ApiPaths.STREAM_ASR 接入后端。只缓存有上限的起始音频；ready 后按序转发，停止后等待 completed。画面静音取决于本地音量，不能根据是否收到 partial 判断。
